SOP-03 AI agents, MCP and skillsScope and overview

Scope and overview

The Model Context Protocol (MCP) lets an AI client call tools on your computer. SEM-view ships an MCP server, semview-mcp, with tools to simulate data headlessly and to drive an open exhibit. emskills skills describe analysis tasks that an agent can run on that data. The steps: install the server, register it with an AI client, connect the exhibit, test commands, use skills, and contribute a skill.

Requirements

  • Node.js 20 or later, and git.
  • A copy of the SEM-view repository: git clone https://github.com/Advanced-EM/SEM-view
  • An MCP client (Step 2).
  • Chrome or Edge for the exhibit. Some browsers block a web page from connecting to a local server.
  • For contributing skills: Python 3.10 or later and a GitHub account.

Safety and privacy

  • The server listens on 127.0.0.1 only and accepts connections only from the exhibit's site and localhost.
  • The exhibit connects only when you select Connect agent, and it shows when an agent is connected.
  • While a training task is running, the exhibit refuses changes from the agent, so recorded practice stays your own.
  • With a cloud model (Claude, OpenAI), your prompts and the tool results, including images, go to that provider. With Ollama, everything stays on your computer.
  • Speech recognition in Chrome is processed by Google. Typed commands are not sent anywhere unless an agent is connected.
Caution. Do not expose port 8792 to a network or tunnel it to the internet. Anyone who can reach it could drive the exhibit.

Step 1

Install the server

git clone https://github.com/Advanced-EM/SEM-view
cd SEM-view/tools/semview-mcp
npm install
node test.mjs          # headless check: all lines should start with "ok"

Note the full path of server.mjs; the client configurations below need it. In the examples it is written /PATH/TO/SEM-view/tools/semview-mcp/server.mjs.

Step 2

Register the server with your AI client

The client starts the server itself when it starts. Register it with one client and restart that client.

Claude Code

claude mcp add --scope user semview -- \
  node /PATH/TO/SEM-view/tools/semview-mcp/server.mjs

Claude Desktop

Edit claude_desktop_config.json (macOS: ~/Library/Application Support/Claude/; Windows: %APPDATA%\Claude\), keeping any servers already listed:

{
  "mcpServers": {
    "semview": {
      "command": "node",
      "args": ["/PATH/TO/SEM-view/tools/semview-mcp/server.mjs"]
    }
  }
}

The same mcpServers block works in Cursor (~/.cursor/mcp.json), LM Studio (mcp.json) and Gemini CLI (~/.gemini/settings.json).

OpenAI Codex CLI

Add to ~/.codex/config.toml:

[mcp_servers.semview]
command = "node"
args = ["/PATH/TO/SEM-view/tools/semview-mcp/server.mjs"]
Note. The ChatGPT app connects only to remote MCP servers at an HTTPS address. semview-mcp is a local server, so use Codex CLI or another local client with OpenAI models. Do not tunnel the server to the internet to make it reachable.

Ollama (local models)

Ollama has no MCP client of its own. Use ollmcp (MCP Client for Ollama) with a model that supports tool calls, such as qwen2.5:7b or qwen3. Save the Claude Desktop block above as servers.json, then:

pip install ollmcp
ollama pull qwen2.5:7b
ollmcp --model qwen2.5:7b --servers-json servers.json

Small local models call tools less reliably. Give short, direct requests, one step at a time.

Result. The client lists the semview server with ten tools. In Claude Code, run claude mcp list; in other clients, look in the tools or connectors menu.

Step 3

Connect the exhibit and verify

  1. Start the AI client from Step 2. This also starts semview-mcp.
  2. Open the exhibit in Chrome or Edge: https://advanced-em.github.io/SEM-view/, or a local copy (python3 -m http.server 8767 in the repository folder, then http://localhost:8767).
  3. In the controls panel, scroll to Voice and agent and select Connect agent. The button changes to Agent connected · Disconnect (Fig. 9).
  4. In the AI client, ask: “What is the exhibit showing?” The agent calls exhibit_status and reports the mode, specimen and optics.
  5. Ask for a change: “Switch to BSE and load nickel.” The exhibit changes, and the agent reports what it did.

Result. The exhibit shows Agent connected, and the agent can read and change it.

Live test from the command line

cd SEM-view/tools/semview-mcp
node test.mjs --live    # then select Connect agent within 90 s

This drives an open exhibit without an AI client: it changes settings, acquires, and checks the answers.

Ports. The exhibit tries ws://127.0.0.1:8792, then 8793. Each AI client starts its own copy of the server, and only one copy can use a port. If two clients are running, the exhibit connects to whichever server holds 8792. Run one client at a time, or start a second one with SEMVIEW_PORT=8793 in its environment.

Step 4

Test built-in and beyond-built-in commands

Open the command bar with the brain button at the top of the controls, or press /. Hold M to say a command instead of typing it. The exhibit handles each sentence in one of four ways.

SentenceWhat happensAgent needed
Exact built-in commandRuns at once (Fig. 10a)No
Close miss or misspelling“Did you mean…?” with buttons; answer yes, no, or “the second one” (Fig. 10b)No
Anything else, with an agent connectedPassed to the agent: “Asked the agent…” (Fig. 10c). The agent receives it through exhibit_wait_for_voice and answers with exhibit_say, acting with the other tools if askedYes
Anything else, no agentNot understood; the exhibit lists examples (Fig. 10d)No

Starting the agent's listening loop

The agent receives sentences only while it is waiting for them. Tell it once, in the AI client:

Listen to me in the exhibit: call exhibit_wait_for_voice, answer each question with exhibit_say in two or
three sentences, use the other semview tools when I ask for something, and keep listening until I say stop.

Step 5

Use emskills skills with the agent

An emskills skill is a folder with a SKILL.md manifest: front matter that names the skill and its tool call, and sections that tell an agent what the skill does, its limits, and how to call it. The registry is at github.com/emskills-mcp/em-skills and listed at emskills.org.

Claude Code

Claude Code loads skills from ~/.claude/skills/<name>/SKILL.md. emskills manifests include the name and description fields it needs.

git clone https://github.com/emskills-mcp/em-skills
mkdir -p ~/.claude/skills
cp -r em-skills/skills/scalebar-calibrate ~/.claude/skills/
cp -r em-skills/skills/sem-topography ~/.claude/skills/

Start a new session and ask, for example: “Simulate an SE image of the cross grating at 10 kV with semview, then calibrate the magnification with the scalebar-calibrate skill and compare with the 463 nm pitch.”

Other clients

Give the agent the skill's SKILL.md as instructions: add it to a Claude Desktop project, reference it from AGENTS.md for Codex, or paste it into the system prompt for an Ollama model.

Typical workflow

  1. The agent produces data: simulate (headless) or exhibit_acquire with save (from the exhibit). Both write .npz with metadata.json holding the calibrations.
  2. The agent runs the skill's tool or reference implementation on that file, following the skill's Usage section.
  3. The agent compares the result with the truth recorded in the metadata, which is known because the data is simulated.
Note. Simulated data with known truth is the main reason to pair SEM-view with emskills: a skill can be tested on exact ground truth before it is trusted on real data.
Caution. Skills run code on your computer. Read a skill's SKILL.md and its reference implementation before installing it, as you would any software.

Step 6

Contribute a skill to emskills

  1. Fork emskills-mcp/em-skills on GitHub, clone your fork, and create a branch.
  2. Create skills/<slug>/ with the files in the table at right.
  3. Write SKILL.md: the front matter below, then the sections Scope, Safety, Usage (a JSON block whose tool equals tool_call) and Reproducibility (one command that runs the check).
  4. Make a small, deterministic fixture with known ground truth, and a reference implementation that recovers it.
  5. Add one line for the skill under ## Skills in the repository README.
  6. Run the validator. It must pass with --run: 
    pip install -r requirements-dev.txt
python3 scripts/validate_skills.py --run
  7. Commit, push, and open a pull request. The same validator runs in CI on the pull request.

Front matter

---
name: cl-dislocation-density
slug: cl-dislocation-density
technique: SEM
category: Spectroscopy
kind: SKILL.md
summary: Dislocation density from dark spots in CL maps
license: MIT
version: 0.1.0
runtime: python 3.11
tool_call: count_dislocations
description: >
  One paragraph for agents: what it does and when to use it.
---
FileContents
SKILL.mdManifest and instructions
examples/invoke.jsonA sample tool call, matching the Usage block
fixtures/sample/Small test input with known truth
fixtures/generate.pyHow the fixture was made
verify.py + requirements.txtReference implementation (Python runtime)
verify.js + package.jsonReference implementation (Node runtime)

Required front-matter keys: name, slug, technique, category, kind, summary, license, version, runtime, tool_call. Techniques: SEM, TEM, STEM, EDS, EELS, cryo-EM, FIB. The slug, name and folder must match, and the version is semver.

Tip. SEM-view can generate fixtures with exact ground truth: simulate writes calibrated .npz data for any mode. CL maps from simulate (mode cl, specimen gan) come with the true dislocation density in the analysis truth: a ready fixture for the example above.
Open candidates. The exhibit's fit_eds, fit_resolution, fit_focus, index_ebsd, fit_cl and mc_summary analyses have no emskills skill yet (Fig. 11b).

Adding a command to SEM-view

New sentences for the built-in grammar go in parseCommand in js/voice.js. New agent tools go in tools/semview-mcp/server.mjs (registerTool), with the matching method in js/agent.js. Add a check to tools/semview-mcp/test.mjs and open a pull request on Advanced-EM/SEM-view.

Troubleshooting

ObservationLikely causeAction
“No agent server at ws://127.0.0.1:8792 or 8793”The AI client is not running, or the server failed to startStart the client; check that it lists semview; run node test.mjs
Connected, but the agent says no exhibit is connectedTwo clients are running; the exhibit joined the other one's serverClose the other client, or use SEMVIEW_PORT (Step 3)
Connect agent fails on the public site onlyThe browser blocks a web page from reaching a local serverUse Chrome or Edge, or a local copy of the exhibit
Questions show “Asked the agent…” but nothing is saidThe agent is not in its listening loopGive the listening instruction in Step 4 again
The agent stops listening after a few questionsCommon with small local modelsRestart the loop; use a larger model; keep requests short
The agent calls the wrong tool or invents argumentsSmall model, or a long multi-part requestAsk for one change at a time; name the setting and value
Changes are refusedA training task is runningFinish or give up the task first
Validator fails on UsageThe Usage JSON or invoke.json does not match tool_callMake the three agree
Validator fails with --runThe reference implementation does not recover the fixture's truthRun the Reproducibility command locally and fix the check
