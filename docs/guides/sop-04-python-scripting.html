SOP-04 Python scriptingScope and overview

Scope and overview

The semview Python package controls the simulated microscope: it changes settings, records detector data as NumPy arrays with calibrations, runs analyses that report the simulator's true values, and sets hidden misalignments (challenges) that score an algorithm against the truth. The same script runs in three places.

Terms used

A challenge is a training task's hidden misalignment, set up for a script instead of a person. The knob is the setting a script reads and changes; the truth is the optics the simulator actually applies. During a challenge the two differ by the hidden amount, as on a misaligned instrument.

Rules

  • While a person is doing a training task in the exhibit, scripts cannot change settings. The exhibit refuses, so recorded practice stays human.
  • Challenge runs are never recorded or shared with the research dataset.
  • Ending a challenge restores the instrument as it was before the challenge.
  • In the IDE, the exhibit pauses while a script runs and redraws when it ends. Keep long loops on a desktop.
  • Live mode listens on 127.0.0.1 only, on the port semview-mcp uses (8792). Run one or the other, or choose another port.
Note. An algorithm that reads the score or the hidden values while it runs is not tested by the challenge. Use score() and reveal() only after the algorithm has finished.

Step 1

Run a first script in the exhibit

  1. Open the exhibit in a current browser and select the terminal button at the top of the controls (Fig. 12a), or Controls → Python scripting → Open the Python IDE (Fig. 12b), or press P.
  2. Wait for the status line to show the Python version. The first time, about 15 MB downloads; later it opens in a few seconds.
  3. Select Examples → Quick start, then Run (or Ctrl+Enter, ⌘+Enter on a Mac).
  4. The exhibit switches to SE imaging of tin spheres at 5 kV. The output shows the probe size, the acquisition with its pixel size, and the image (Fig. 12c).
  5. Edit the script and run it again. Save writes it as a .py file; Open loads one. Help lists the calls.

Result. The script changes the exhibit, and its output appears below the editor.

import semview as sv

sem = sv.connect()
sem.set(mode="se", specimen="sn", kV=5, current_pA=100, fov_um=5)
print(sem.state()["probe_nm"], "nm probe")
img = sem.acquire()
print(img, img.calibration["pixel_um"] * 1000, "nm per pixel")
sv.show(img, "SE image, tin spheres on carbon")
Note. The editor keeps your script in this browser between visits. Python runs on your computer; no code is sent anywhere.

Step 2

Install the package on a desktop

The headless backend runs the simulator's own JavaScript in Node.js, so the package is installed from a copy of the repository and stays linked to it.

git clone https://github.com/Advanced-EM/SEM-view
python -m venv .venv && source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -e "SEM-view/tools/semview-py[live,plot,test]"
pytest SEM-view/tools/semview-py/tests                        # all tests should pass
python SEM-view/tools/semview-py/examples/quickstart.py

Headless

  1. Check Node.js: node --version must report 20 or later.
  2. In Python, sem = sv.connect() starts the simulator in a background Node process. It stops when the script ends, or with sem.close().
  3. Use it as a context manager to close it reliably: with sv.connect() as sem: …

Result. sem.info()["backend"] is "headless", and a typical acquisition returns in a fraction of a second.

Note. To use a copy of the repository somewhere else, set the environment variable SEMVIEW_ROOT to its folder.

Live (driving an open exhibit)

  1. Close any AI client that runs semview-mcp, or choose another port.
  2. Run the script. sv.connect("live") prints that it is waiting for the exhibit.
  3. In the exhibit, select Controls → Voice and agent → Connect agent within the timeout (120 s by default).
  4. The script continues, and the exhibit follows each call on screen.
sem = sv.connect("live", port=8792, timeout=120)

Result. The script prints “Exhibit connected.”, and the exhibit shows Agent connected.

Caution. Live mode listens on 127.0.0.1 only and accepts the exhibit's own site and localhost. Do not forward the port to a network.

The calls

Every call is the same on the three backends. sem is the object sv.connect() returns.

Microscope

CallReturns, or does
sem.set(**settings)Changes settings (next page); returns what was done
sem.state()Settings and beam: probe size and its budget (source, Cₛ, Cc, diffraction, aperture), depth of field, sharpness, charging
sem.command(text)Runs a plain-language command: "focus plus 0.5"
sem.autofocus()The instrument's auto focus and stigmation (disabled in challenges that test your own)
sem.profile(**fields)The digital twin's instrument profile: read it, pick a preset, or set calibrations (magCal, scanAspect, scanShear, Br, edsFWHM, …)
sem.acquire(steps=None)An Acquisition (below), after advancing the simulation so it reflects the settings (an EBSD map runs to the end, EDS counts for 3 s)
sem.analyze(name)calibrate_scale, fit_resolution, fit_focus, reconstruct_relief, fit_eds, phase_map, index_ebsd, fit_cl, mc_summary; the result includes the true values
sem.step(n)Advances n frames of 50 ms: EDS counts accumulate, maps fill in, the wobbler swings
sem.info()Modes, specimens, settings, analyses, challenges and instrument presets available
sem.challenge(id, seed)Starts sem-focus-stig, sem-aperture-align, sem-insulator or ebsd-setup
sem.score() · sem.reveal()The challenge's score from the true optics · the hidden values
sem.end_challenge()Restores the instrument as it was
sv.show(x, title)Draws a 2D image or a 1D profile (IDE output, or matplotlib)

Settings apply in a fixed order whatever order you write them: specimen, mode, then the optics. Choosing a mode applies its usual conditions (for example, EBSD sets 70° tilt, at least 20 kV and nanoamps; CL inserts the mirror at 10 mm working distance), so set those values after it or in the same call.

Errors. A refused or invalid call raises SemviewError with the reason, for example unknown setting defocus or a training task is running.

Step 4

Test an automation algorithm with challenges

A challenge hides a misalignment, so the knob readings no longer show the true optics. The algorithm works only from what a real microscope gives it: images and measurements. Afterwards, score() grades the result against the truth. A fixed seed repeats the same misalignment, so algorithms are compared on the same cases.

  1. Start a challenge with a seed: sem.challenge("sem-focus-stig", seed=1).
  2. Run the algorithm. It may read state() (the knobs), acquire, and analyze, but not score() or reveal().
  3. When it stops, record sem.score().
  4. Repeat for a set of seeds, and report the scores together.
  5. Call sem.end_challenge() to restore the instrument.

The example: automatic focus and stigmation

examples/auto_focus_stig.py corrects focus and two-fold astigmatism from the images alone:

  • Its measure of quality is the image's gradient energy: largest when the probe is smallest.
  • A golden-section search finds the sharpest setting of one knob over its whole range, in 14 steps, using only acquired images.
  • The knobs are searched in the order a microscopist adjusts them: focus, stigmator X, stigmator Y; then the three again, which settles the small coupling between them.
  • The knob readings are off by unknown amounts, so it never uses absolute values: it only compares images.

Headless; tin spheres, 450 nm field, 10 kV; about 90 acquisitions and 24 s per seed. The images carry shot noise, so the same seed ends slightly differently from run to run (in the IDE as well); it passes the same way.

What the score means. The task scores the blur that focus and astigmatism add, against the probe diameter. Here every seed ends with less than half a probe diameter of added blur, so the image is as sharp as the probe allows, even with up to a quarter of a micrometre of astigmatism left: at this magnification and convergence that residue adds about a nanometre of blur at most.

Step 5

Batch data and regression tests

A labelled dataset

Simulated data comes with exact ground truth, which makes it useful for training and testing analysis models. Run this headless:

import json, semview as sv

with sv.connect() as sem:
    sem.set(mode="se", specimen="sn", kV=10, fov_um=0.45, realistic=True)
    sem.autofocus()                                   # a sharp, stigmated start
    f0, (x0, y0) = sem.state()["focus_um"], sem.state()["stig"]
    labels = []
    for i, df in enumerate((-0.6, -0.3, 0, 0.3, 0.6)):
        for dx, dy in ((0, 0), (0.5, 0), (0, 0.5), (0.4, -0.4)):
            sem.set(focus_um=f0 + df, stig_x=x0 + dx, stig_y=y0 + dy)
            name = f"focus_{i}_{dx:+.1f}_{dy:+.1f}.npz"
            sem.acquire().save(name)
            labels.append({"file": name, "defocus_um": df, "astigmatism_um": [dx, dy]})
    json.dump(labels, open("labels.json", "w"), indent=1)

The labels are relative to the auto focus result, which lands within a few hundredths of a micrometre of the true focus and stigmation. Each .npz also carries the full instrument state in its metadata.

Reproducibility

  • Record sem.state() and sem.info() with every result.
  • Fix challenge seeds. Use realistic mode (realistic=True) when shot noise matters to the algorithm.
  • Note the repository commit (git rev-parse HEAD); the simulator improves between versions.

An algorithm as a regression test

Put the benchmark in a test so that changes to the algorithm or the simulator cannot silently make it worse:

# tests/test_autofocus.py
import pytest, semview as sv
from auto_focus_stig import align     # tools/semview-py/examples

@pytest.fixture(scope="module")
def sem():
    with sv.connect() as m:
        yield m

@pytest.mark.parametrize("seed", range(1, 9))
def test_autofocus(sem, seed):
    sem.challenge("sem-focus-stig", seed=seed)
    align(sem, verbose=False)
    assert sem.score()["score"] >= 85
    sem.end_challenge()

The SEM-view repository runs its own tests this way on every pull request (.github/workflows/tests.yml), with Node.js 20 and Python set up in the workflow.

Voltage-series example. examples/find_e2.py steps the voltage down on an uncoated alumina inclusion until it stops charging. With seed 7 it stops at 1.8 kV, against a hidden E2 of 1.82 kV.

Speed

An SE or BSE image takes about a quarter of a second, a through-focus analysis about half a second, and a 40 × 40 EBSD map a few seconds. The simulator computes on the CPU in JavaScript. The calls do not depend on how it computes, so a future WebGPU backend could speed up the same scripts without changes; the IDE's status line shows whether the browser offers WebGPU.
